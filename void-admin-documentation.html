1. Executive Summary & Migration Scope

The VOID Admin Panel originally relied on a lightweight mock server (json-server at http://localhost:5000 reading from db.json). This architecture posed critical security vulnerabilities, lacked transactional consistency, offered zero role enforcement, and failed when deploying to production.

The objective of this migration was to transition all four admin panel views (Inventory Manager, Order Manifest, User Directory, and Admin Dashboard) to the Django REST Framework backend while strictly preserving the visual identity, dark monospace aesthetics, and responsiveness of VOIDCORP.

3. End-to-End System Architecture & Workflows

3.1 Authentication & Administrative Authorization Flow

The application utilizes a defense-in-depth security model:

  1. Session Restoration (Client): On app boot, restoreSession() in Redux calls /api/v1/accounts/token/refresh/ using the HttpOnly cookie. The backend issues a short-lived access token kept strictly in JavaScript memory.
  2. Identity & Role Serialization: The frontend calls /api/v1/accounts/profile/. UserProfileSerializer inspects is_staff / is_superuser and returns "role": "admin".
  3. Route Protection (Client-side): AdminRoute.jsx inspects the Redux user state. If user.role !== "admin" or the session is unauthenticated, the user is redirected away.
  4. Server-Side Enforcement (DRF): Frontend route protection is non-authoritative. Every admin endpoint checks permission_classes = [IsAdminUserOrStaff]. Requests without valid JWT claims or without staff/superuser flags are rejected with HTTP 401 or HTTP 403.
[ React Client ]
   |
   |-- 1. HTTP GET /api/v1/orders/admin/ (Authorization: Bearer <JWT>)
   v
[ Django Middleware (Authentication & JWT Verification) ]
   |
   |-- 2. Authenticates request.user
   v
[ IsAdminUserOrStaff.has_permission(request, view) ]
   |
   |-- user.is_authenticated AND (user.is_staff OR user.is_superuser) ?
   |      |-- YES: Execute Admin View QuerySet & Return JSON
   |      \-- NO:  Return HTTP 403 FORBIDDEN

3.2 Centralized Interceptor Flow (apiClient.js)

All outbound requests through catalogClient, ordersClient, and accountsClient pass through a unified Axios interceptor chain:

  • Request Interceptor: Automatically injects Authorization: Bearer <accessToken> and X-CSRFToken headers for mutation verbs (POST, PUT, PATCH, DELETE).
  • Response Interceptor: Catches 401 Unauthorized errors. If the request has not already retried, it collapses concurrent 401s into a single refreshPromise hitting /token/refresh/, updates the access token in memory, and replays all pending requests transparently.

4. Detailed Working of Each Backend Function & Class

4.1 apps/accounts/permissions.py

class IsAdminUserOrStaff(BasePermission):
    def has_permission(self, request, view):
        return bool(
            request.user
            and request.user.is_authenticated
            and (request.user.is_staff or request.user.is_superuser)
        )
  • Purpose: Single source of truth for administrative access control.
  • Working: Evaluates boolean validity of authenticated user identity. Ensures regular customers with active accounts cannot reach administrative routes even if they forge frontend state.

5. Detailed Working of Each Frontend Admin Page

5.1 InventoryManager.jsx (Inventory Management)

  • Query (adminProducts): Fetches all product records via catalogClient.get("/products/"). Passes raw records through normaliseProduct() to resolve relative Django media URLs against VITE_CATALOG_API_URL.
  • Filtering Engine: Real-time client-side filtration on search query (name/UID), series dropdown (FLOW, VOID, RITE, FORM), and stock status (Low Stock ≤ 10, Out of Stock = 0).
  • Mutation (saveMutation): Maps modal form state (including base64 data-URIs from file dropzone) to backend schema. If editing, sends PATCH /products/<id>/; if creating, sends POST /products/. On success, invalidates both adminProducts and customer products caches and shows toast confirmation.
  • Decommission Protection: Triggering "Wipe" opens a confirmation modal. If the backend rejects deletion due to existing orders, catches HTTP 400 and displays an error toast explaining that the variant cannot be removed.

5.2 OrderManifest.jsx (Order Manifest & Dispatch)

  • Query (adminOrders): Fetches orders via ordersClient.get("/admin/"). Normalizes backend order payload into display attributes, mapping model statuses (e.g. shipped → Deployed).
  • Filtering & Search: Filters transactions by UUID, customer name, customer email, fulfillment status pill (Pending, Deployed, Delivered, Cancelled), and timeframe (Today, This Week, All Time).
  • Detail Modal (Manifest): Clicking "Manifest" opens customer details, delivery address, phone, item breakdown with line-item rates, and total liability in INR.
  • Status Mutation: Admin select dropdown triggers ordersClient.patch("/admin/<uuid>/", { status }) with immediate cache invalidation.

5.3 UserDirectory.jsx (User Directory & Clearance)

  • Query (adminUsers & adminOrders): Fetches user directory via accountsClient.get("/admin/users/") and orders via ordersClient.get("/admin/").
  • Customer Intelligence Modal: Clicking "Inspect" evaluates lifetime value (total spent in INR), average order value, purchase frequency, affinity brand series, and transaction history.
  • Security Clearance Mutation: Admins can suspend (is_active: false) or restore (is_active: true) customer accounts. The action button is disabled for the root administrator's own profile to prevent lockout.

5.4 AdminDashboard.jsx (System Telemetry & Analytics)

  • Query (adminDashboard): Hits ordersClient.get("/admin/dashboard/"). Eliminates multiple disparate API calls.
  • Visualization Elements:
    • Transaction Performance Matrix: Responsive SVG AreaChart plotting 30-day gross revenue.
    • Individual Payment Streams: BarChart plotting recent individual captured transactions.
    • Financial HUD: Real-time counts of gross revenue (INR), active user accounts, and dispatch volumes.
    • Top Seller Variants: Ranked showcase of best-performing products with units sold, total revenue, and product thumbnails.
